leasegate

Nothing on your machine holds standing power. Every process gets a lease.

Time-limited, scoped, human-approved access to the credentials on a workstation, for CLI tools and AI agents.

A developer's or administrator's workstation holds a lot of power: SSH keys, API tokens, browser sessions, cloud credentials. They usually sit in plain files and environment variables, readable by every program the user runs. That was tolerable while the only thing running commands was the human. Now AI agents and automated tools run on the same machine with all of it in reach, and a single prompt injection can turn them.

A gate is a small tray application that holds a credential, or the only link to something powerful, and hands out access to it on three terms. The operating system says which process is asking. A human sees that process's whole chain, from the program up to the terminal that started it, before approving. And the approval is scoped and ends on its own.

The gates

gitgate

git and the GitHub CLI, with the right identity for every folder and no credential lying around.

sshgate

Server SSH keys that no program can read, and a human who sees every login.

bwgate

A Bitwarden or Vaultwarden vault that no program can open by itself, and a human who sees every request.

cdpgate

Your real browser, driven only by the programs a human has approved, for the profiles and websites they chose.

The library

leasegate

The Java library every gate is built on: process chain, anchors, grants, approval windows, tray, vault. Build your own gate.
